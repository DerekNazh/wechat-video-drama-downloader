## 二、合规红线（MUST）

1. **本分支产物不得作为收费产品对外销售**——wx_channels_download 为 MIT+Commons Clause，禁止 Sell 其功能价值。任何对外商业化行为（付费下载器/订阅/点数计费）必须：
   - 先完成自研替换（见下），或
   - 另行获得 ltaoo 商业授权（书面）
2. **禁止把 exe / 上游源码直接二次打包分发**（改名、加壳、封装后对外发布均属禁止范围，除非获得授权）。
3. **Apache 2.0 的 res-downloader**：允许商用，但分发时必须保留其版权声明；不得移除 LICENSE/NOTICE。
4. 上游微信客户端升级导致 exe 失效时，**按既定策略直接拉上游最新版**（外部维护者持续更新，不自行修复其内部逻辑）。

## 三、自研替换策略（本分支长期目标）

> 用户拍板（2026-10-29）：基于上游**代码逻辑自研**，不直接商业化改造上游代码。自研实现不受 Commons Clause 约束（自研代码不含上游版权）。

| 能力 | 上游来源 | 自研方向 | 状态 |
|---|---|---|---|
| 视频号下载链路 | wx_channels_download（代理+注入，MIT+Commons Clause） | **必须自研重写**（照逻辑自己写，全新代码不受 Commons Clause 约束）——纯 API 直调（红狐/TikHub），零注入零代理 | 已由 master 号匣验证可行（v1.89 架构） |
| 视频解密 | WechatSphDecrypt（ISAAC-64 keystream） | Python 内嵌解密：ISAAC-64 + 前 128KB XOR | ✅ 号匣 v1.70 端到端实测通过，可移植复用 |
| 资源嗅探 | res-downloader（**Apache 2.0**） | **可直接商用，逻辑不用重写**（2026-10-29 用户拍板）；仅需保留 Apache 2.0 义务：①保留 LICENSE 版权声明 ②修改文件标注变更 ③含 NOTICE 则附带 | ✅ 用户拍板直接商业化 |

**自研优先原则**（2026-10-29 用户拍板细化）：
- **MIT+Commons Clause 项目（wx_channels_download 链路）**：必须按上游**逻辑**自研重写为自有代码（算法/协议/流程参考，代码全新），禁止复制源码、禁止二次打包分发 exe。
- **Apache 2.0 项目（res-downloader 嗅探）**：可直接商业化复用其逻辑，**不用重写**；但分发时保留 LICENSE/NOTICE 与版权声明。

## 四、执行要求

- 任何改动涉及上游 exe / 上游源码引入：先查本文件对照许可证，再动手。
- 引入新的开源依赖：必须核验其 LICENSE，并在本文件追加登记（项目名/许可证/约束/核验日期）。
- 上游许可证冲突（如 WechatSphDecrypt 待核验结果）→ 记录后提交用户拍板，不得静默继续。
- **res-downloader 商业化引用**：入库即附其 LICENSE 文本（放 third_party/licenses/），改动文件头部标注变更来源。
